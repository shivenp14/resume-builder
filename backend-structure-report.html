Resume Builder backend

Repository structure and contents report · generated September 7, 2026

What it is: a local-first FastAPI backend for maintaining verified resume source material, tailoring it to jobs with Codex, reviewing proposed changes, and producing immutable LaTeX/PDF resume revisions. AI output is proposal-only: it cannot silently alter verified source records.

Persistence model

Verified source library

ContentItem represents experience, projects, education, and activities. Bullet holds rewriteable/locked statements, tags, supporting facts, and preference metadata. Skill stores canonical names, categories, aliases, notes, and verification.

Resume composition

BaseResume stores the template, section order, and layout/contact settings. BaseEntry selects source items and exact bullet IDs in a defined order. Unique constraints prevent duplicate entries within a base resume.

Job tailoring

Application, JobAnalysis, MissingConfirmation, Proposal, and OptimizationRun represent the job, AI analysis, evidence gaps, suggested changes, and an auditable model-run record.

Immutable output

Revision retains a materialized resume snapshot plus optional TeX/PDF paths, page count, and status. Revision numbers are unique per application.

Tailoring workflow

  1. Create an application linked to a base resume and its job description.
  2. Analyze the description through the locally authenticated Codex CLI.
  3. Compare requirements against the verified library and resolve missing-information prompts.
  4. Generate an evidence-grounded proposal; it selects entries and may suggest allowed bullet rewrites.
  5. Approve the proposal only after validation. A source fingerprint rejects stale proposals if the library has changed.
  6. Generate an immutable revision and compile its TeX/PDF artifact under generated/applications/<id>/revision-<n>/.

Services and safeguards

ComponentCurrent behavior
codex_provider.pyCalls the local authenticated Codex CLI with gpt-5.6-luna, low reasoning, default tier, read-only sandboxing, ephemeral execution, strict output, timeouts, and no OpenAI API keys exposed to the subprocess.
llm_prompts.py and llm_schemas.pyVersioned prompts and strict Pydantic outputs. Job/resume text is treated as untrusted input, and the model must ground suggested claims in supplied evidence.
validation.pyChecks snapshot references and duplicate IDs; prevents locked-bullet rewrites; rejects unsupported numeric, technology, and named-entity claims.
renderer.pyRenders the Jinja2 template with StrictUndefined, escapes LaTeX, invokes latexmk, uses a revision-local TeX cache, and derives page count via pdfinfo with a pypdf fallback.
SQLite configurationForeign-key enforcement is enabled for each connection. Schema uniqueness protects base-resume entries and application revision numbering.

Checkpoint import

python -m backend.seed_checkpoints parses the checkpoint LaTeX resumes and seeds the local database. Its normal seed path replaces imported records. The --migrate-verified mode is non-destructive: it transactionally backfills contact metadata and evidence-backed rewriteability only for explicit owner-matched, checkpoint-tagged records.
